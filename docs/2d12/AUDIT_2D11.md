# Amber World 2D 11 — технический аудит

**Статус:** первичный статический аудит исходников и данных. Это не отчёт о прохождении игры: Godot 4.7 в среде аудита отсутствует, поэтому запуск сцен, импорт ресурсов и выполнение GDScript-тестов пока не подтверждены.

## 1. Состав поставки

- Исходники проекта Godot находятся в `Исходники/game/`; главный проект — `game/project.godot`.
- В архиве также присутствует Windows-сборка `AmberWorld.exe` + `AmberWorld.pck`.
- В исходном дереве обнаружено: 140 GDScript-файлов, 43 тестовых GDScript-файла, 79 PNG, 54 TRES, 7 TSCN, 24 JSON и 116 OGG.
- Проект заявляет Godot 4.7, renderer Compatibility, viewport 1366×800.
- Внешний XLSX `amber2d/assets_list/Amber 2D — список текстур.xlsx`, на который ссылается `ART_DIRECTION.md`, в архиве отсутствует.

## 2. Подтверждённые существующие системы

| Подсистема | Реализация / данные | Фактический статус по исходникам |
|---|---|---|
| Глобальная карта | `map_shaders.gd`, `world_physics.gd`, `art/map`, `art/terrain` | Сложная многослойная 2D-карта и атмосферные эффекты уже существуют; требуется runtime-проверка и визуальная оценка |
| Мир и переходы | `worlds/worlds.gd`, `world/settlements.gd`, `world/ruins.gd` | Есть отдельные менеджеры миров, поселения и руины; тесты переходов используют doubles, дополнительно нужны интеграционные прогоны с настоящими сценами |

| Ресурсы и сбор | `world/foraging.gd`, `data/world/forage.json`, `world/camp.gd` | Биомно-зависимый сбор, инструменты и лагерь реализованы отдельными модулями |

| Крафт | `city/craft.gd`, `data/cities/recipes.json` | 13 рецептов, две мастерские; присутствуют заказ, самостоятельное изготовление, расход материалов и обучение |

## 3. Ключевые разрывы и риски

### P0 — сохранения

`world_save.gd`: `VERSION = 6`; `list()` удаляет файлы сохранений с отсутствующим/несовпадающим заголовком и отдельно удаляет legacy `user://world_save.dat`. Это опасная политика для обновления игры: игрок может потерять старые сейвы без резервного копирования и миграции. До любых изменений формата требуется резервное копирование, мигратор версий и тесты на копиях сейвов. Не запускать проверку на пользовательском `user://` с реальными сохранениями.

### P1 — квестовая система

`quest_journal.gd` прямо описывает ручной ввод заданий игроком; `endless_quests.gd` формирует повторяемые поручения на основе прогресса города. Не обнаружен самостоятельный слой данных сюжетной кампании с устойчивыми ID целей, условиями, событиями, наградами, автопрогрессом и сохранением состояния квеста. Это главный функциональный разрыв относительно целевого дизайна 2D 12.

### P1 — контентный каталог

Предметы и рецепты хранятся отдельно в JSON, а часть боевого контента — в `.tres`. Нет единого проверенного реестра, связывающего предмет с категорией, источником получения, применением, иконкой, мировым представлением, экипировкой, рецептом и справочной статьёй. Сначала нужен реестр/валидатор, затем UI-каталог.

### P1 — художественные заглушки

В исходниках остались прямые пометки `[ЗАГЛУШКА]` и `[ВРЕМЕННО]`, в частности: фасад/крыша здания (`city/city_world.gd`), числовые параметры проникновения (`city/wall_climb.gd`), опыт за поручение (`city/city_world.gd`), радиус обзора (`world/fog.gd`), баланс сбора (`world/foraging.gd`), частота встреч (`battle/encounters.gd`), износ (`characters/wear.gd`), обзор с башни (`characters/cast.gd`). Это не означает, что функции отсутствуют; это означает, что авторские комментарии фиксируют временный характер части чисел/визуала.

### P2 — тестирование

В `game/tests` 43 скрипта проверок, что является хорошей основой. Однако ряд тестов миров/смерти/транспорта явно использует `tests/doubles` для города и боя. Такие тесты проверяют переходы и контракты, но не заменяют end-to-end тест настоящих сцен. Godot runtime отсутствует в текущей среде, поэтому зелёный/красный статус тестов не присваивается.

## 4. Проверки данных, выполненные статически

- `cities/items.json`: 69 предметов.
- `cities/recipes.json`: 13 рецептов; все входные и выходные ID рецептов найдены в базе предметов.
- `cities/s001.json`: 29 NPC, 43 здания, 5 стадий роста.
- `lore/notes.json`: существует отдельный массив/словарь лорных записок для кодекса.
- В проекте присутствуют 43 тестовых скрипта; полный список — в `tests/`.

## 5. Решения для 2D 12

1. Не переписывать глобальную карту и город с нуля: сначала закрепить их контракты тестами.
2. Создать единый `ItemDatabase`/валидатор над существующими JSON и TRES без дублирования источников истины.
3. Добавить полноценную квестовую модель и подключить к существующим city-growth/endless quests через адаптеры.
4. Создать игровой справочник, строящий страницы из тех же данных предметов, ресурсов, рецептов, инструментов, эффектов и способностей.
5. До любых релизных изменений внедрить миграцию сейвов и тестирование на копиях.
6. Заменять художественные заглушки только в рамках единого арт-стандарта ART_DIRECTION.md.

## 6. Ограничения аудита

Не выполнены: импорт Godot, запуск меню/игры, выполнение 43 тестов, профилирование, проверка экспорта, ручной осмотр всех игровых экранов и длительный игровой прогон. Эти пункты остаются обязательными до заявления о стабильности.
