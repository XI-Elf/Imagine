# Amber World 2D 12 — реестр и переработка ассетов

## 1. Художественный контракт

Следовать `ART_DIRECTION.md`: рисованная 2D-графика сверху/в ракурсе три четверти, не пиксель-арт; тушевой контур, приглушённая акварель, земляные тёплые цвета и холодные тени; прозрачный фон у игровых объектов; единая точка опоры, масштаб, источник света и направление камеры. Проклятые земли показывать свечением и изменённой природой; в интерфейсе использовать «проклятые земли» и «влияние проклятия», не «радиация».

## 2. Текущие группы

| Группа | Каталог | Что делать |
|---|---|---|
| Глобальная карта и маски | `game/art/map/` | Сохранить топологию/маски; проверить читаемость биомов, рек, границ, высот и LOD |
| Текстуры биомов | `game/art/terrain/` | Сохранить текущие 12 типов земли и слой свечения; привести названия/описания UI к лору проклятия |
| Мир и декорации | `game/art/storybook/` | Инвентаризировать каждый PNG: объект, размер, pivot/anchor, прозрачность, статус, использование |
| UI | `game/art/comic_ui/` | Проверить единые рамки, контраст, состояния кнопок, масштабы и локализацию |
| Медальоны города | `game/art/medallion/` | Связать каждый этап с фактическим состоянием поселения |
| Бой и предметы | `battle/battle_icons.gd`, `characters/item_art.gd` | Вывести procedural-иконки из статуса финального контента; создать таблицу иконка/спрайт/экипировка |
| Техно-артефакты | `game/art/storybook/tech_*.png` | Перерисовать временные грубые спрайты в общем стиле, сохраняя их силуэт и назначение |

## 3. Статус по текущей поставке

- В проекте найдено 79 PNG в исходном дереве; группы map — 8, terrain — 13, storybook — 34, comic_ui — 7, medallion — 6 (каталоги могут содержать вложенные/дополнительные форматы).
- Внешний XLSX со списком текстур отсутствует, поэтому нельзя достоверно заявить, какие ассеты из авторского списка являются финальными.
- `ART_DIRECTION.md` прямо указывает на временные `tech_*` и процедурно рисуемые боевые значки.

## 4. Обязательные поля реестра ассетов

Для каждого визуального объекта завести запись: `asset_id`, `path`, `entity_id`, `kind`, `biome`, `source_status` (final / revise / placeholder / missing), `world_scale`, `display_scale`, `anchor`, `shadow`, `animation`, `icon_path`, `world_sprite_path`, `equipment_slot`, `used_by`, `notes`. Реестр должен генерироваться/валидироваться из файлов, а не поддерживаться вручную в нескольких местах.

## 5. Порядок переработки

1. Экспортировать полный список файлов, размеров, альфа-канала и фактических ссылок из сцен/скриптов.
2. Сопоставить изображения с ID предметов, NPC, зданий, существ, ресурсов и биомов.
3. Проставить статусы; отдельно выделить отсутствующие ассеты и временные процедурные рисунки.
4. Сделать приоритетные наборы: предметы/ресурсы, инструменты, экипировка, NPC, интерактивные объекты, техно-артефакты, здания.
5. Проверить все изображения в игровых масштабах и на светлом/тёмном фоне.
6. Не заменять отсутствующую графику примитивами и не менять имена файлов без миграционной таблицы.

## 6. Критерии готовности

- У каждого предмета есть читаемая иконка; у размещаемых предметов — спрайт мира; у экипировки — корректный слот/отображение на персонаже.
- Все интерактивные объекты имеют согласованные anchor, тень, сортировку и hitbox.
- Ни один новый ассет не нарушает силуэт, угол камеры, палитру и прозрачный фон арт-брифа.
- Временные `tech_*` и procedural icons имеют явный статус, владельца задачи и критерий замены.
