# Amber World — 2D 12: отчёт о слиянии

База: `amber2d/Amber Game — 2D 11 (исходники).zip` (коммит a28ee14). Архив не менялся, работа шла в копии (ветка `claude/project-thread-rnsgds` репозитория XI-Elf/Imagine).
Источники: 6 архивов 2D12 из папки проекта. Проверка: Godot 4.7.2.stable.official (linux, xvfb, рендер Compatibility/opengl3).
Правила слияния от Huzzah: «сравнивать фактический код, не CHANGELOG», затем (2026-11-04 17:39) «приоритет у новых файлов; если не работают — доработать до рабочего», и (17:42) «кампании Pass5 и Pass6 — где проработаннее, то и ставим».

## 1. Как связаны архивы (по diff, не по описаниям)

| Архив | Фактически |
|---|---|
| Audit_and_Roadmap | 2D 11 + `world_save.gd`, `tests/code_audit_checks.gd`, документы |
| FieldGuide_Visual_QuestPass (Pass2) | Audit + справочник выжившего (`field_guide.gd`, `item_glyph.gd`, тест), поручения города в «Заданиях», `items.json` с category/description, 7 МБ референсов |
| Visual_City_Pass3 | Pass2 + `city_world.gd` (штрихи тайлов, знак неразведанной постройки) |
| Visual_Ruins_Pass4 | Pass3 + `world_decor.gd` (руины в слое мира), `settlements.gd` (застройка миниплана) |
| Main_Campaign_Pass5 | Pass4 + `world/quest_campaign.gd` (линейная кампания из 5 глав в коде) |
| Campaign_Emblems_Pass6 | **отдельная ветка от 2D 11**: `story/campaign.gd` + `campaign.json`, 2 босса, эмблемы, значки, портреты |

Цепочка Audit→Pass5 линейная (каждая включает предыдущую), Pass6 — параллельная. Слияние: Pass6 целиком, поверх — Pass5 трёхсторонним merge (общий предок 2D 11), 4 конфликта (`hero_window.gd`, `city_world.gd`, `items.json`, `worlds.gd`) разрешены вручную.

## 2. Выбор по системам

| Система | Взято | Почему |
|---|---|---|
| Сохранения (`world_save.gd`) | Audit/Pass5 | В 2D 11 `list()` при просмотре удалял сохранения другой версии (пункт P0 аудита 2D 10). Новая версия ничего не удаляет, читает `.bak`, `delete()` чистит `.bak/.tmp`. Формат и VERSION=6 те же. Проверено на реальном файле 2D 11 (новый тест `save_compat_checks`). |
| Основная кампания | **Pass6** (`story/campaign.gd`, `data/story/campaign.json`) | Pass6 проработаннее: 6 глав, 5 персонажей с мотивами, 4 развилки с флагами/репутацией/последствиями, 2 босса со своими локациями, 3 сюжетных предмета, данные в JSON. Pass5 — 5 линейных глав в коде, без выбора, награда только деньгами. Обе пишут одну переменную и один ключ сохранения `campaign` в разных схемах — вместе жить не могут. Решение подтверждено повторным сравнением потока «Сравнить сборки кампании и эмблем». |
| Хуки кампании | Pass6 + фильтр Pass5 | Бесконечные поручения больше не двигают сюжет (`not endless` из Pass5). Добавлен сброс кампании при новом герое (в Pass6 его не было, в Pass5 был). |
| Вкладка кампании | Pass6, перенесена | У Pass6 11-я вкладка при 10 клавишах (1–9,0): подпись «1 Кампания» дублировала «Характеристики», горячей клавиши не было, и это ломало правило «меню героя — 10 разделов» (правка 8). Содержимое вкладки целиком — первым разделом «Заданий». |
| Поручения города в «Заданиях» | Pass2–5 | Работают на существующем API роста города, тесты зелёные. |
| Справочник выжившего (I → «Дневник») | Pass2–5, доработан | Две плоские рамки `StyleBoxFlat` ломали `comic_ui_checks` → заменены на коміксные `ComicUI`; добавлена категория «Сюжетные» для предметов Pass6; подписи «кг»/«мон.» и категории — через I18n. |
| `items.json` | Pass5 + Pass6 по ключам | Pass5: category+description у всех 69 предметов (ни одно старое поле не изменено). Pass6: 3 сюжетных предмета. Итого 72. |
| Значки предметов (`item_art.gd`) | Pass6 | 3 значка сюжетных предметов + штриховка; `item_art_checks` 126/126 (72 вещи). |
| Эмблемы, метки сюжетных мест | Pass6 | Герб Эшвика меняется по решениям кампании; 4 новые фигуры; метки мест после открытия главы. |
| Боссы (5 `.tres`) | Pass6 как есть | `human` оставлен по умолчанию (true): это механизмы/сторожа, с них падают монеты и брухт, а не шкуры. Совет первого отчёта ставить `human=false` отклонён — дал бы шкуры и портрет волка. |
| Город: штрихи тайлов, знак неразведанного | Pass3 | Только живописный слой, детерминирован, проходимость не трогает; рисуется в кешируемом слое земли (перерисовка при смене троп). |
| Застройка миниплана поселений | Pass4 | Колодцы, лавки, кузни, храмы вместо только домов/трактиров. |
| Руины на общей карте | **Pass4, доработан** | По правилу «приоритет новых» взят слой мира Pass4. Проблемы были: (1) двойная отрисовка с `cast.gd`, (2) в лесу храм тонул в деревьях, (3) обысканные руины не отличались. Доработка: `cast.gd` больше не рисует спрайт, только притенение обысканных и подпись; в лесу вокруг руин поляна 16 м и здание выше крон. Снимки проверены (`qa/ruins_shots.gd`). |
| Портреты NPC | **Pass6, доработан** | Финальный слой Pass6 рисовал текстуру прямо в `_draw` и в рендере Compatibility выходил сплошной белый прямоугольник поверх лица (снято на 4.7.2). Сделано рабочим: ручной арт роли — погрудный кадр через дочерний `TextureRect` + `AtlasTexture` (верхние 42% спрайта), лёгкое «дыхание» и подсветка при наведении. Роли без спрайта — прежний живой портрет кодом (глаза за курсором, рот по настроению) с контурами/волосами/бородой Pass6. Снимок: `qa/portrait_shots.gd`. |
| Документы и референсы сборок | вынесены в `docs/2d12/` | 7 МБ референсов не используются кодом и попадали бы в .pck. |

## 4. Сохранённые решения 2D 11

Формат сохранений и VERSION=6; запись tmp→bak→rename; механика руин (`world/ruins.gd`, обыск на F); сетка и проходимость города; единое меню героя на I с 10 разделами; живой портрет для ролей без арта; украинский по умолчанию.

## 5. Исправленные ошибки

1. Список сохранений удалял файлы другой версии (база) → больше не удаляет (тест: файл v5 скрыт, но на диске).
2. Состояние кампании из чужой схемы читалось бы как своё (Pass6 брал любой словарь) → `StoryCampaign.migrate()`: без `version=1` — кампания с начала, лишние поля отбрасываются, числа из JSON приводятся к int, номер главы ограничен.
3. Новый герой наследовал пройденную кампанию предыдущего (Pass6) → сброс в `_attach`.
4. Бесконечные поручения двигали сюжет (Pass6) → фильтр.
5. 11-я вкладка при 10 клавишах, дубль подписи «1» (Pass6) → раздел в «Заданиях».
6. `StyleBoxFlat` в справочнике ломал `comic_ui_checks` 33/34 (Pass2–5) → коміксные рамки.
7. Руины рисовались дважды и не гасли после обыска; лесные терялись в кронах (Pass4) → один слой, притенение, поляна.
8. Портрет Pass6 — белый прямоугольник поверх лица → рабочий погрудный арт.
9. Кампания, справочник, описания 69 предметов, боссы и способности были только по-русски при украинском по умолчанию → 201 строка переведена, тексты кампании идут через `I18n.tree` как остальные данные. `i18n.py check`: без перевода 0.
10. `story_campaign_checks` на `assert` в безголовом режиме зависал бы без итога при ошибке → счётчик проверок и код выхода.

## 7. Оставшиеся проблемы

- Портреты по ручному арту не показывают настроение (рот/брови) и не следят глазами за курсором — это свойство живого портрета кодом, у роли без спрайта оно осталось. Несколько ролей делят один спрайт (кузнец, кожевник, горожанин — `villager`; старейшина и знахарка — `woman`, как задумано в Pass6). Нужны свои портреты по ролям.
- Сюжетные локации (часовня ≈3,5 км севернее Эшвика, маяк ≈3,5 км восточнее и 2,5 км южнее) заданы координатами; проходимость к ним глазами не проверялась.
- Баланс боссов не оценивался.
- Миграции сохранений версий < 6 по-прежнему нет (как и в 2D 11): такие файлы скрыты, но не удаляются.
- В логе `balance_checks` остаются старые ошибки `battle_core.gd` `_ai_close_in` (были и в 2D 11).
- События кампании Pass5 (`codex`, `battle_win`) в главы Pass6 не вписаны; хук прочтения записки вызывает событие, которого нет в целях глав, — безвредно.
